# 讨论成员异常后的恢复

一次异常只跳过该成员在当前人类消息之后的发言；其他可用成员继续。不会因为其他成员又说了几句话，就在后台重发这份失败的请求。

下一条普通人类消息会让已确认失败的成员重新参与，包括回复包含多个 JSON 对象、补正后仍无法解析、明确失败的连接等情况。被点名的轮次仍只调用被点名的成员。暂停指令和程序准备的审议材料不自动恢复异常成员。

- 连续三轮失败后暂停自动恢复，排查后可点击重新加入；有效的新回复清除连续失败次数。一次格式补正仍属于同一轮失败，不计成两轮。
- 请求结果未知时，发送新消息也不会重新调用该成员；需先核对是否已经执行操作，再显式确认继续。
- 额度或请求频率受限的成员保留跳过状态，恢复后手动重新加入。
- 旧版本已经保存的普通失败也适用新规则，无须清空聊天记录。失败记录、原始错误和用量继续保留，自动恢复只针对新的发言请求。

恢复后的发言提示要求只处理当前消息；需要再次操作时先核实实际状态，避免重复修改。唯一对象、重复字段、轮次和版本核对保持原样，失败内容不作为有效控制指令采用。

界面在在场栏区分“本轮跳过”和“待重新加入”，并说明自动恢复或手动核对的条件。`tests/discussion-recovery.test.ts` 使用独立 SQLite 存储和本地模拟成员验证调度、重启、连续失败、结果未知及格式校验；界面冒烟验证三种状态和窄窗口显示。这些测试不发送真实模型请求。
