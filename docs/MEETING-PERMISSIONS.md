# 项目会议室权限

项目会议室不再隐式覆盖成员设置。每个项目可在聊天区选择模式：

- **协作工作（默认）**：继承执行端默认权限及人物覆盖。使用实际项目目录，允许的操作直接在该目录或用户允许的文件范围内执行。此处修改不经过项目流程副本的验收写回。
- **只读讨论**：保留成员配置的文件范围和联网选择，禁止写入和命令。读取、搜索仍可用于核实讨论内容。

茶歇室的普通聊天、举手投票、纪要、图像请求、成员汇报和正式项目任务继续使用各自原有的边界。正式项目任务的独立副本和验收流程没有改成会议室直接修改。

## 配置、生命周期与回执

`Project.meetingMode` 通过 `project.update` 保存；未设置的项目默认 `collaborate`。成员原始权限不会被模式切换覆盖。

普通项目会议发言及点名回复在入队时冻结 `Run.roomAccess`：模式、真实项目目录、文件/命令/联网权限、可写状态和自动批准规则。上下文、原生工具配置、模型说明及界面回执使用同一份结果。严格审批不会被“新工作会话自动批准”覆盖。

模式、成员权限或目录改变后，下一轮保留旧会话为历史并创建新原生上下文；在途轮次继续使用已冻结的权限。运行时指纹包含权限收据。历史消息保留自己的权限收据，即使对应运行从快照或存储中移除，也不会显示成后来的模式。

## 原生能力差异

DSH 使用对应原生沙箱和工具策略；Codex、Claude Code、Antigravity 使用已有会话/启动策略。Qoder/通用 ACP 的读取审批可在已明确允许的范围自动处理；修改和命令仍按本轮权限及审批选择处理，不能通过自动批准绕过只读拒绝。

原生程序只报告部分操作时，AIROOM 不能把审批通道表述成完整的操作系统隔离。连接能力说明继续保留这些限制。ZCode 的协作写入仍要求其支持的权限组合；其原生读取没有可核对的项目路径隔离，项目会议选择“仅限工作区”时会在模型请求前明确失败，提示调整该成员设置或换执行端，不静默扩大范围。

“不限制”允许任务需要时读取其他目录；“仅限工作区”的项目会议以实际项目目录作为工作区，不再以隐藏聊天目录充当项目工作区。额外只读目录列表尚未增加；可继续使用已有的成员文件范围选择。

## 验证

- `tests/meeting-access.test.ts`：真实 Engine 调度、六类成员上下文、文件读取/写入、模式切换时的在途冻结、旧原生上下文退休和历史回执。
- `tests/meeting-access-native.test.ts`：本机已安装且未修改的 DSH 0.2.1-rc.2、ZCode 3.16.2，独立未登录配置和本地模拟 API；实际跨目录读取、协作写入及只读工具清单。
- `tests/meeting-access-acp.test.ts`：独立 ACP 子进程按 Qoder CN 的连接路径发送读、写、命令审批，核实自动允许、只读拒绝及严格审批，并检查实际测试文件。
- `tests/ui/meeting-access-smoke.mjs`：真实 React/Engine 界面保存、重载、权限展示、历史回执及窄窗口布局。

这些验证不发送真实模型请求，不使用个人账号或 API Key。
