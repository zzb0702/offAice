# Qoder / Qoder CN 账号额度

在 AIROOM 的“用量与额度”中找到使用 Qoder CLI 或 Qoder CN CLI 的成员，点击“刷新额度”。检查连接时也会查询一次；成员卡及侧栏显示最近回报的简要状态。使用新源码构建需先从托盘退出旧进程，再运行 `Start-AIROOM-Dev.cmd`。

按原生账号回报显示当前计费周期的套餐 Credits、附加 Credits、组织资源包、套餐类型和到期时间。字段缺失时保持未提供；没有对应资源包时不补造卡片。套餐到期与额度恢复不同，不以到期时间推测刷新时间，不添加五小时或每周窗口。

Qoder 资源池可能互为补充，套餐池用完不代表附加额度也用完。自动发言只依据原生账号总用量和 `isQuotaExceeded` 判断；资源池各自的百分比不作为全账号耗尽依据。账号额度过期或获取失败时不以旧值暂停调用，也不把未知值显示成零或满额。报告十五分钟后显示待更新。

## 查询与账号边界

- 使用当前清单连接的官方可执行程序，沿用该连接的 AIROOM 私有 `QODER_CONFIG_DIR` / `QODERCN_CONFIG_DIR` 和当前官方登录或已配置的个人访问令牌；不回退到宿主的全局登录。
- 新建短期原生 SDK 控制进程，只发送 `initialize` 和 `get_usage_info` 两个控制请求。无用户消息、模型任务、续接会话或 SDK 运行依赖；不改变原有聊天使用的 ACP 适配。
- 禁止会话持久化，清空内置工具和 MCP，忽略用户/项目/本地设置来源，使用 `dont_ask` 权限模式；原生回调和工具请求一律拒绝。不使用跳过权限参数。
- 初始化及额度控制分别限时，协议输出有大小上限。无界面控制不可用、超时、协议异常、服务只返回 session 统计等情况显示额度不可用，不以会话 Credits 推算账号余额。
- 仅白名单额度字段进入快照和存储，不保留账号 ID、头像、升级/明细链接、会话统计和原始凭据。原生加密账号文件仅做哈希，不解密或复制。
- 当前登录文件、令牌或连接配置变化会使旧缓存失效；查询中账号文件变化则丢弃迟到结果。原生认证自动刷新也可能使当次结果失效，重新刷新额度即可，不需要据此退出登录。

## 验证边界

当前本机 Qoder CN 原生控制已成功返回真实套餐及附加额度，查询没有发送模型任务。国际版路由与结构通过模拟 CLI 验证，不作为真实国际账号验收。

测试覆盖原生子进程协议、两版私有目录、异常与 session-only 响应、超时、账号切换、资源池和总额度区分、真实 Electron 界面刷新与重启。桌面截图使用测试 Credits，不能当作实际账号额度证据。
