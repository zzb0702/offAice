# ZCode CLI 自定义中转/API

从系统托盘退出旧版 AIROOM，再运行 `Start-AIROOM-Dev.cmd`。打开“设置与连接 → 连接与版本 → ZCode CLI”，在“登录方式”中选择“自定义中转/API”。

填写服务提供方的 API Key、模型 ID 和 API 根地址，然后点击“保存密钥并检查”。根地址示例为 `https://relay.example/v1`，不应附加 `/chat/completions`。默认接口格式为 OpenAI Chat Completions；也可明确选择 OpenAI Responses 或 Anthropic Messages。

此模式不要求 BigModel 或 Z.ai 官方账号登录，按所填服务的规则计费。密钥使用系统凭据保护加密保存；输入框留空会保留已保存的密钥，清除使用单独按钮。切换到自定义服务不会读取或转发官方账号的登录凭据。

连接检查会启动真实 ZCode、加载模型配置并读取原生模型选项，不发送模型请求。检查通过后，新建话题发送短消息测试真实服务。中转需要支持对应的流式协议；使用工具时，需支持工具定义、工具调用和工具结果回传。当前验证覆盖文字、文件工具和本机模拟中转的思考档位请求，未验证任意自定义模型的图片输入或真实服务的推理效果。

保存 API 连接后，同一连接卡片中会显示“思考程度”。可选档位来自当前 ZCode 原生模型规则，例如本版的 GLM-5.3 与 GLM-5.3-Flash 返回 low、high、max；并非所有模型都有相同选项。选择后点击设置窗口底部的“保存设置”，从下一轮任务生效；“模型默认”表示跟随 ZCode 为该模型提供的默认档位。自定义 API 的模型仍在上方“API 模型”输入框修改，不重复显示第二个模型编辑器。

如果只显示“模型默认”或“开启/关闭”，说明 ZCode 没有为该名称返回更细的强度档位；中转自定义别名可能只能匹配通用规则。应核对服务提供的准确模型名称，不要把模型改成服务不支持的名称。AIROOM 不伪造可用档位；所选值会交给 ZCode 原生接口并按对应协议传入请求，真实中转仍可能拒绝或忽略该参数，需要通过服务方支持说明和实际请求验证。

ZCode 原生配置中的 Chat Completions 协议名是 `openai-chat-completions`。它与界面默认的 OpenAI Chat Completions 对应。服务地址、接口格式和模型严格使用保存的值，不会自动改投 BigModel、Z.ai 或其他服务。

ZCode 原生接口读取明文 API Key 配置，不承诺 `${ENV}` 插值。AIROOM 按官方配置格式生成一次性配置文件：Windows 上先将目录访问权限制为当前用户，其他系统使用仅当前用户访问的权限；关闭原生进程后清理临时配置。长期设置和渲染器快照不含密钥。官方登录资料与自定义 API 数据目录独立。

保存新的连接方式、地址、接口或默认模型时，会清理原会话的原生绑定并保留 AIROOM 历史，后续运行使用新的连接配置。修改前需要停止正在运行的任务。普通终端的 ZCode 配置和已安装 CLI 版本保持原样。

本次仅改造 ZCode；Qoder CN 未改动。

官方配置依据：[ZCode CLI 配置说明](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/docs/usage/03-config.md)。具体兼容性以当前安装版本的实际验证为准。
